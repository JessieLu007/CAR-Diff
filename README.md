## Usage

### 1. Data and column declarations

Each dataset is a file `data/<name>.csv`, registered in `data/datasets_info.json`:

```json
{
  "chronic_kidney_disease": {
    "numerical":   ["age", "bp", "..."],
    "categorical": ["al", "su", "..."],
    "target": "class",
    "minority_class": "ckd"
  }
}
```

The `target` column is automatically added to the categorical columns and modeled jointly with all other columns.
Once registered, the dataset appears in `utils.common.DATASETS` and can be referenced by name or by index (the order in the json file).
The five-fold pipeline in Section 2 additionally requires `num_col_idx`, `cat_col_idx` and `target_col_idx` (0-based column indices) in `data/datasets_idx.json`. The quickstart in Section 3 does not.

### 2. Reproducing the paper with five-fold CV

The fold indices (`splits/*_5fold.json`) ship with the repository. The imputed splits (`splits/*_imputed/`) and `data/Info/` are generated by `run_cv` and `make_tabkde_info`, so run `run_cv` first, then `gen_baselines` and `prepare_tabsyn_folds`.
Splitting and imputation use a fixed seed (2026) and depend on the scikit-learn version; results may differ slightly from the paper in other environments.

```bash
# Train Ours (autoregressive categorical head; cat_ar defaults to True).
# Fixed budget of 200 epochs, no validation set, final weights are used.
python -m experiments.run_cv --dataset chronic_kidney_disease --fold 0 1 2 3 4 \
    --tag main --model "cat_ar=True" --train "target_epochs=200" --seed 42
# Ablation: w/o AR (categorical columns sampled independently given the numerical representation)
python -m experiments.run_cv --dataset chronic_kidney_disease --tag noar --model "cat_ar=False"
# Another ablation: --model "share_decoder=False"; legacy / sampled / nointeract: see the tags below

# Repeated sampling per fold (5 in total: s0 comes from training, s1..s4 from this step)
python -m experiments.resample_ours --dataset chronic_kidney_disease --device cuda --js 1 2 3 4

# Comparison methods (--dataset / --fold take a single value, so loop over folds; 5 samples per fold)
for k in 0 1 2 3 4; do
  python -m evaluation.gen_baselines --dataset chronic_kidney_disease --fold $k \
      --methods smote ctgan tvae tabddpm tabkde --n-samples 5
done
# For diabetic_data, add --ddpm-lr 1e-4 for tabddpm

# Evaluation (--hp = h256_t200_3_<tag>)
python -m evaluation.run --dataset chronic_kidney_disease --fold 0 1 2 3 4 --hp h256_t200_3_main \
    --baselines smote ctgan tvae tabddpm tabkde
# Recompute only some metrics: --only shape cpt ; recompute everything: --redo ;
# TabSyn results: --tabsyn-root <dir>

# Aggregation (no command-line arguments; set OURS_MAIN etc. at the top of scripts/aggregate_main.py;
# output goes to agg_out/)
python scripts/aggregate_main.py
```

Result folders and tags keep the names used during the experiments. When building the tables, `ours_h256_t200_3_<main tag>` is reported as Ours and `ours_h256_t200_3_<noar tag>` as w/o AR.
The legacy / sampled / nointeract ablations in the paper use older code: `git checkout ablation-cat-switches`. The w/o AR variant corresponds to tag `experiments-final`; use that code version if you resample w/o AR results trained with it.

### 3. Without five-fold CV: quickstart.py

Split the data yourself. The test set is optional and used only for evaluation.
The quick interface supports smote / ctgan / tvae / tabddpm; TabKDE and TabSyn are only available in the five-fold pipeline.

```bash
# Option A: register the dataset in data/datasets_info.json and use it by name
# (data/<name>.csv is used as the training set)
python quickstart.py run --dataset hepatitis --test my_test.csv --repeats 5
# Option B: custom files; spec.json has the same format as one entry of datasets_info.json
python quickstart.py run --train train.csv --test test.csv --spec spec.json --out runs/demo

# Or step by step: fit -> sample -> eval
python quickstart.py fit    --dataset hepatitis --test my_test.csv
python quickstart.py sample --dataset hepatitis --repeats 5
python quickstart.py eval   --dataset hepatitis [--fake runs/hepatitis/synthetic_s1.csv]

# Comparison methods (smote ctgan tvae tabddpm; output: runs/<name>/baselines/<method>_s<j>.csv)
python quickstart.py baselines --dataset hepatitis --methods smote ctgan --n-samples 5
python quickstart.py eval --dataset hepatitis --fake runs/hepatitis/baselines/smote_s0.csv
```

Common overrides: `--epochs`, `--seed`, `--model "dim_hidden=128"`, `--training "batch_size=32"`.
The training set must contain at least `batch_size` rows (default 64).
If you see `libgomp: Invalid value for environment variable OMP_NUM_THREADS`, quickstart fixes it automatically;
for other scripts run `export OMP_NUM_THREADS=8` first.
`evaluation/gen_baselines.py` imports `synthcity` at the top, so synthcity must be installed even if you only run smote.

### 4. TabKDE and TabSyn

- **TabKDE**: see `third_party/tabkde/README.md`. Run `bash third_party/tabkde/setup_tabkde.sh <official zip>`,
  then `python -m evaluation.make_tabkde_info` for the five-fold pipeline.
- **TabSyn**: see `third_party/tabsyn/README.md`. Run `bash third_party/tabsyn/setup_tabsyn.sh <official zip>`
  (official repository: https://github.com/amazon-science/tabsyn, Apache-2.0; default hyperparameters are used), then
  `python -m experiments.prepare_tabsyn_folds --dataset <name> [--all] --seed 2026 --n_folds 5`
  to convert our five-fold splits into TabSyn's data format. Evaluate the generated data with `evaluation.run --tabsyn-root third_party/tabsyn/tabsyn-main`.
